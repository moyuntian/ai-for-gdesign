## 组件高亮色

组件高亮色是指在用户界面中用于突出强调某个组件元素或交互状态的特定颜色，可以用于如按钮、链接、标签、选中状态、焦点状态、悬停状态等，以增强交互效果和可视化反馈。

### 用于软件产品

在软件产品中，我们采用蓝色#0067D1为默认的组件高亮色，并以此颜色延展出其他相关交互状态颜色。选择此颜色不仅是由于蓝色相较于其他颜色具有更广的普适性和接受度，更加关键的是，蓝色#0067D1具有足够的对比度，可保证在不同屏幕和环境下的可读性和可见性。此外，对于视障人群，蓝色也依然能保障清晰的识别度。 

![原文图 1](color-images/image1.png)

### 用于门户官网

门户官网场景建议统一使用深灰色#191919作为高亮色使用。门户网站通常会有大量图像内容和信息需要呈现，选择更加稳重和沉稳的深灰色#191919作为官网门户的组件高亮色，可以为用户提供更加舒适和稳定的浏览体验。

![原文图 2](color-images/image2.png)

## 公司辅助色

公司辅助色分为两大类：一类为灰色系公司辅助色、一类为彩色系公司辅助色。 本规范的公司辅助色基于《华为视觉识别规范手册》V2.0 的原有辅助色色值在数字场景下进行了适配，提高明度与饱和度，并对色相进行了延展。

## UI色彩应用指南

H Design 色彩规范以Color Token的方式管理所有UI场景用色，将色彩命名与实际用途、语义相结合，贯穿设计与开发工作流。这不仅有利于帮助我们了解如何使用颜色，也能最大程度地减少未来色彩系统演进与更新后的维护成本。场景配色方案是整个色彩系统的核心，也是设计过程中实际运用在UI界面里的颜色。 有关Color Token完整列表和使用描述，请查阅设计参数列表。

### 无障碍配色方案

考虑到色彩障碍人群对色彩的感知度有限，根据网页内容可访问性指南（WCAG），H Design 色彩系统优化了默认图表配色，以满足用户对色彩的辨识度。 WCAG AA 标准对比度规则： 对于小于24px的任意大小的界面文本与图形元素，需要满足4.5:1的对比度( WCAG 1.4.3 ) 对于大于24px的任意大小的界面文本与图形元素，需要满足3:1 的对比度( WCAG 1.4.11 )

## 代码色应用指南 

StarCode 星辰代码配色主题，从 H Design 数字场景色板精选了适用于代码语法领域的色值，并同时面向 Web 和 IDE 的使用场景构建了色彩的语义化映射。设计师可在实际使用时，基于代码类型确定具体色值，并通过本规范提供的规范资源和开发建立协作流程，实现好用又好看的代码配色。

### 语法类型和对应色板

构建代码语法高亮配色方案的第一步是对常见语法进行分类，分类的基础源自Highlight.js 的命名系统。 

Highlight.js 是一个用于网页代码语法高亮的 JavaScript 库。它通过自动检测代码语言并应用不同的样式来高亮代码片段，使网页上的代码更易于阅读。它被广泛应用于技术博客、文档网站和代码编辑器等场景，优势是轻量级和易于集成。

经过归纳，当前常用的语法类型共计 9 大类，包含约 35 个 hljs 类名（后续将基于用户场景和业务持续新增），将 H Design 中选定的 Color Token 与 Highlight.js 内置类名进行绑定，可得到下图所示的映射关系。我们看到的 .hljs-comment，.hljs-function 等名称就是 Highlight.js 的语法类名，而“注释内容”、“程序结构”是语法聚类后的大类名称。

![原文图 18](color-images/image18.png)

值得注意的是，我们需要尽可能减少色相数量，以提升代码观感，使其更简约耐看。因此，在无需特别强调的语法类型中，建议使用灰阶区分主次。例如，在“数据与字面量”大类下的 string、literal、number 等语法均被赋予了灰色，而带有判断逻辑的 boolean 则被赋予了薄荷绿，而注释内容，如 comment，quote 等相较于其他类型优先级最低，因此使用明度更小的灰色。

建议各领域设计师以上述介绍的配色逻辑为基础，同时针对具体业务场景中需要重点强调的语法类型进行高亮。经测试，被高亮的语法类型比例不建议超过 80%，使用的色相数量不建议超过 10 种，否则将导致代码可读性和观感品质显著下降。

### 语义映射表

本色板需要支持 Web 和集成开发环境（IDE）2 类典型代码显示场景，因此仅有基于 Highlight.js 构建的映射关系是不够的。Highlight.js 虽面向的场景较多，但难以进行更精细的语法类型识别和定义。

例如在下图展示的映射关系中，“类型与系统”类主要支持的语法类型主要为 .hljs-type，.hljs-title，.hljs-class，但在像 DevEco 这样的 IDE 软件中，可以实现更多且精细的类型配置，如 Interface，Class，Enum，Type parameter 等。像这类配置颗粒度的差异，会导致 Web 和 IDE 场景无法有效的使用同一套色板。

![原文图 19](color-images/image19.png)

因此我们需要一个基于语义的映射系统，不仅能同时包含 Web 和 IDE 场景中支持的主要配置项，还能构建起两者之间的映射关系，并以此为基础提供建议的颜色。

![原文图 20](color-images/image20.png)

上图所示的表格即为语义映射表，从左至右分别呈现了“功能大类，功能子类，Highlight.js 类名，IDE 设置项名，频率，深色色值，浅色色值，常见用途示例和选色理由。表格顺序代表了实际选色的思考逻辑，具体如下：

第 1 步：当需要确定某个语法的高亮色值时，优先确定该语法所在的功能大类和子类。例如，在 ArkTS 语言中，“import”属于程序结构中的关键字类型。

第 2 步：明确功能大类和子类后，基于业务场景查看 Highlight.js 类名或 IDE 设置项名（网页场景：Highlight.js，IDE 场景 ：IDE 设置项名）。例如，“import”的 Highlight.js 类名为 .hljs-keyword，IDE 设置项名一般为 Keyword。值得注意的是，表格中的 IDE 设置项名基于 DevEco 整理而成，并不代表行业所有集成开发发软件，实际使用时可能存在出入。

第 3 步：明确深色和浅色模式下对应的色值。例如，“import”的色值在深色模式下为“#F8CD75"，浅色模式下为“#C98208”。右侧的“场景用途”和“选色理由”供设计师在敲定色值前确认类型是否有误。

通过上述方法，即可完成对某一种语法类型的配色。同时，建议设计师在落地阶段始终基于这份语义映射表和开发、测试同事进行沟通和编辑，这将极大提高协作和落地效率。
